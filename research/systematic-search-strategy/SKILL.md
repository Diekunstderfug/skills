# 医学检索式与 MeSH 关键词树

接受研究问题、关键词、已有检索式或种子文献；沿用已经明确的范围，只有缺失信息会实质改变范围时才询问。默认简短交付；实际检索始终保留多库覆盖和可续接的检索记录。

## 工作方式

七步是可复用的框架，不是每次都必须从头跑完：

| 步骤 | 做什么／何时需要 |
|---|---|
| 1. 定范围 | 理解问题或已有检索式，复用已经明确的范围 |
| 2. 定概念块 | 同义词 OR、必要概念 AND；不机械加入所有 PICO 要素 |
| 3. 构建词汇 | 核实 MeSH 与层级、扩自由词，形成紧凑关键词树 |
| 4. 测试修订 | 基础语法与解析检查；适量实测有变化的查询 |
| 5. 验证漏检 | 有种子、已知漏检或正式综述需要时展开；其余标记未评估 |
| 6. 扩展多库 | 实际检索时尽量覆盖相关数据库，逐平台适配查询 |
| 7. 记录交付 | 实际执行时持续记录进度与缺口；按任务规模交付 |

只问 MeSH、关键词树或修改检索式时，调用相关步骤。要求搜文献／继续检索时，包含第 6、7 步；先读已有记录，再执行剩余或变更部分。明确 Meta／系统综述时展开正式验证。不要把检索主题中出现“meta-analysis”当作正式综述任务。

MeSH 构建时读 [词汇与树](references/methods.md#词汇与树)，基础检查时读 [基础校验](references/methods.md#基础校验)。未核实的词暂作自由词；未执行的检查明确标注。修改已有检索式时保留原式并解释影响召回的改动。

默认回复只包含：

- 一棵紧凑的关键词树，标注 MeSH、自由词及必要的范围说明；可直接附核实来源链接。
- 可直接复制的检索式；请求多库时按数据库／平台分别给出。
- 简短校验结论：已做什么、关键修改／警告、尚未验证什么。

用户只要求改一句、查一个词或只给检索式时，按其要求缩减。实际检索另用一份 [检索记录](references/methods.md#检索记录与续接) 保存过程，回复只概括各库状态、主要缺口和记录位置，不逐项展示全部日志。不生成一组独立报告或图片，不把小规模实测变成全文献下载。用户要求执行检索时继续完成执行，不停在提供检索式。

## 多库与执行

执行文献检索时，尽量覆盖更多相关学术数据库，记录计划、已完成和待处理的来源；零命中、失败与不可访问来源都保留。检索中持续更新记录，而不等结束后凭记忆补写。只写 PubMed 检索式的任务无需扩展成多库检索。

使用可用的 `paper-lookup`、NCBI Entrez 或直接公开 API，逐平台转换语法。不要将 PubMed 字段或 MeSH 原样套到其他库，也不要把语义搜索当成等价的布尔检索。不需要商业搜索或 AI 配图服务。

基础校验、种子命中、记录下载完整性分别报告；任何一项都不能单独证明“查全”。零命中不是接口失败，也不自动导致删除数据库或有依据的候选词。

## 何时展开正式流程

只有用户明确要做 Meta 分析、系统综述、正式范围综述或明确索要完整检索方法／审计材料时，读取 [正式综述扩展](references/methods.md#正式综述扩展)。仅说“查全”“多搜几个库”也要多库执行并记录进度，但不自动生成正式方法报告。

正式任务在已有检索记录上增加独立种子验证、深入诊断和方法说明，默认仍合并为一个文件。AI 自查标注为自查，不宣称完成独立 PRESS 同行审查。不因缺少种子或同行审稿人而停掉可以继续的工作。

后续筛选和综合交给 `literature-review`；数据库执行能力沿用现有工具。本技能不复制上游脚本或引入强制暂停的状态机。指南依据与借鉴范围见 [来源](references/methods.md#来源)。
